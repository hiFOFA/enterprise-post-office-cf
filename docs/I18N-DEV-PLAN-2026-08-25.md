## 1. 现状架构（执行 AI 必须先理解的事实）

### 1.1 i18n 体系

```
frontend/src/i18n/
├── locale-registry.ts      # 6 语言注册表：zh / en / es / pt-BR / ja / de
│                           # 含 label、browserMatches、naive-ui locale、turnstile locale
├── utils.ts                # DEFAULT_LOCALE='zh'，FALLBACK_LOCALE='zh'（键缺失回退）
│                           # getPreferredLocale(stored, browser)：stored → browser → FALLBACK
│                           # getStoredLocale()：读 localStorage 'preferredLocale'
├── index.ts                # createI18n：locale=getInitialLocale()（恒 'zh'），fallbackLocale='zh'
├── message-registry.ts     # 消息注册表：905 键，en+zh 为内联源（SourceLocale）
├── messages.ts             # en/zh 从 registry 构建嵌套树；de/es/ja/pt-BR 从扁平文件构建
├── app.ts                  # useScopedI18n(namespace) → t(key)
└── locales/source/
    ├── de.ts es.ts ja.ts ptBR.ts   # 扁平格式 "ns.key": "译文"（各 627 行）
    └── (en/zh 无独立文件，内联在 message-registry.ts)
```

### 1.2 语言切换机制

- **URL 路径前缀**是唯一规范源：`router.beforeEach`（`frontend/src/router/index.js:84-93`）取路径第一段解析语言，**无前缀时强制 `DEFAULT_LOCALE`（zh）**：
  ```js
  const routeLocale = resolveSupportedLocale(to.path.split('/')[1])
  const resolvedLocale = routeLocale || DEFAULT_LOCALE   // ← 浏览器语言在这里被无视
  i18n.global.locale.value = resolvedLocale
  ```
- `preferredLocale`（localStorage `preferredLocale`，`frontend/src/store/index.js:103`）只被写入、**从不决定显示语言**（仅 line 91-93 初始化 store 自身）。
- Header 的语言下拉（`frontend/src/views/Header.vue:61-105, 251-259`）通过 `replaceLocaleInFullPath` + `router.push` 切换，切 zh 时去前缀。
- **登录页没有 Header**：`EnterpriseLogin.vue` 是 `position:fixed; inset:0` 全屏页，语言下拉在 DOM 里但被盖住 → 用户在登录页无法切语言。
